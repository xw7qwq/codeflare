# CPH 本地编译加速

本工作区使用 `.cph/scripts/cph-g++-fast.py`，实际编译器仍为 Homebrew GCC 16，语言标准 GNU++23。源码继续直接写 `#include <bits/stdc++.h>`，包含完整的 GCC 万能头，不需要修改提交代码。

- CPH、全局 C++ 配置和两个 VS Code 编译任务均启用 `-Werror=return-type`：非 void 函数或 lambda 存在缺少返回值的路径时，直接报编译错误并标出源码行。macOS ARM 上此类代码可能执行到编译器生成的 `brk` 指令，表现为 `SIGTRAP`；重新编译不能修复源码中的未定义行为。
- CPH 默认 `-O0`：优先缩短改代码后的编译等待，程序运行可能比 `-O2` 慢。不要用该模式判断极限数据的运行时间。
- `Cmd+Shift+B`：默认最快编译任务，参数与 CPH 一致。
- “终端 → 运行生成任务”中的“C/C++: 竞赛快速编译 (GNU++23)”：保留原任务名称，使用 `-O2`，适合评估算法运行速度。
- 若要让 CPH 也使用 `-O2`，把工作区 `.vscode/settings.json` 中 `cph.language.cpp.Args` 的 `-O0` 改为 `-O2`，下次运行生效。

加速器按编译参数维护预编译头，检查其全部头文件依赖，并使用 ccache 缓存目标文件。只包含万能头的常见单文件代码还可直接复用可执行文件；其他普通源码通过 ccache 检查本地头文件后再决定是否需要链接。缓存以源码、参数、工具链和相关依赖为依据；编译失败不会执行旧缓存。

预编译头在源码实际的 `#include` 位置生效，因此不会强制改变万能头之前的宏定义。自定义 include 搜索路径、外部库、多文件、预处理、汇编输出等特殊调用交给原始 GCC。检测到主源码、普通本地头文件或编译宏中的 `__TIME__` 等时间宏时，也使用原始 GCC，避免复用过期时间。

缓存位于 `~/.cache/cph-gcc-fast-v2`，不进入仓库。每份预编译头约 190 MB，O0/O2 至少两份；不同参数或编译环境会按需生成独立缓存，第一次可能需要几秒。工具链或预编译头依赖变化后会重新生成。最终可执行文件最多保留 256 份。需要清理时先停止编译，再删除该缓存目录；下次会重建。GCC 主版本升级后若 `g++-16` 不再存在，需要更新脚本中的 `GPP` 和 VS Code 的编译器路径。

`CPH_VERBOSE=1` 可显示缓存不可用时的回退原因；排查编译器本身可直接调用 `/opt/homebrew/bin/g++-16`。脚本只给编译器子进程设置空 `ZDOTDIR`，避免 macOS 汇编器启动 zsh 时加载无关配置，不修改用户 shell 配置。

CPH 样例旁边显示的毫秒数是程序运行阶段时间，不是编译耗时。重编译时还会受电脑当前负载、文件缓存以及首次启动二进制影响。

实现依据：[GCC 预编译头](https://gcc.gnu.org/onlinedocs/gcc/Precompiled-Headers.html)、[ccache 预编译头与外部校验和](https://ccache.dev/manual/latest.html)。
